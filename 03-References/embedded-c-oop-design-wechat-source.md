## 核心内容摘要

文章用 LED、按键和软件定时器示例说明：C 语言虽然没有 `class` 和 `this`，但可以用结构体收拢状态，用函数显式接收对象指针，用初始化函数建立合法状态，从而实现面向对象的基础组织方式。文章重点不在继承、多态或虚函数表，而在对象化思维的入门层：状态归属、接口操作、封装边界和生命周期。

## 关键结论

- 嵌入式 C 项目进入工程化阶段后，核心问题往往是模块边界、实例管理和硬件适配，而不仅是功能跑通。
- `struct` 可以用来描述对象状态，例如 GPIO 端口、引脚和有效电平共同描述一个 LED 实例。
- C 语言里的“方法”本质上仍是普通函数，但通常把对象指针作为第一个参数，常命名为 `self`。
- 封装不是简单地把数据和函数放一起，而是限制外部随意修改内部状态。
- 更严格的 C 语言封装可以使用不透明指针：头文件只暴露类型名和接口，结构体定义放在 `.c` 文件中。
- 对象化设计必须关注生命周期：创建或声明、初始化、使用、反初始化或销毁。

## 待核查问题

- 文章示例偏教学，需要结合真实驱动、RTOS 任务、通信协议栈进一步验证适用边界。
- 不透明指针常涉及动态内存；在 MCU 裸机或安全关键场景中，需要评估是否使用静态实例池。
- C 语言对象化设计要注意并发访问、ISR/任务上下文、内存生命周期和可测试性。
