# Embedded Knowledge Base

这是一个面向嵌入式软件工程师的个人知识库。目标不是堆放笔记，而是把原始资料经过校核、理解、重写和关联后，沉淀成可复用、可追溯、可扩展的工程知识。

## 目录结构

- `00-Inbox/`: 临时入口。新上传的 PDF、网页链接、截图、零散想法先放这里。
- `01-Knowledge/`: 已审核整理的主题知识，按领域分类。
- `02-Projects/`: 项目学习、调试记录、问题复盘和可复用方案。
- `03-References/`: 原始资料索引、外部链接、标准文档和数据手册记录。
- `04-Review/`: 待核查、待改写、存在疑问或需要交叉验证的内容。
- `90-Templates/`: 笔记、资料入库、项目复盘和审核模板。
- `CHANGELOG.md`: 知识库更新记录。
- `DECISIONS.md`: 分类、命名、工具和流程等长期决策记录。

## 入库原则

1. 先保留来源，再整理内容。
2. 重要结论必须标注依据、适用条件和不确定性。
3. 同一知识点优先合并成一篇清晰主题笔记，避免多个碎片重复存在。
4. 面向复用写作：结论、原因、步骤、例外、常见错误都要明确。
5. 每次成批更新后，在 `CHANGELOG.md` 中记录变更。

## 标准工作流

1. 收集：把 PDF、链接或原始摘录放入 `00-Inbox/`。
2. 建档：使用 `90-Templates/source-note.md` 建立资料来源记录。
3. 校核：把待确认内容放入 `04-Review/`，至少标明疑问点。
4. 整理：使用 `90-Templates/concept-note.md` 改写为正式知识笔记。
5. 关联：补充相关主题、项目案例、适用场景和反例。
6. 追踪：提交 Git 变更，并更新 `CHANGELOG.md`。

## 命名约定

- 文件名使用小写英文、数字和连字符，例如 `freertos-task-scheduling.md`。
- 中文标题写在 Markdown 一级标题中。
- 领域目录保持稳定，不为单篇资料频繁新增顶层目录。
- 不确定或未审核内容不要直接放入 `01-Knowledge/`。
